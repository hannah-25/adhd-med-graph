## Freshness Rules

- Update docs in the same change as code when architecture, workflow, API, data, or security behavior changes.
- Mark uncertain statements as `ASSUMPTION`.
- Mark known stale or incomplete work as `TODO(owner, YYYY-MM-DD, reason)`.
- If docs and code disagree, inspect code first and update docs.
